# 数据线：通用 RL 跟踪器（"优化器"）设计稿（11-06，设计和可行性，未训练）

**目标（Jiming 经用户转达）：** 一次训练出一个 policy。以后同一类任务（移液枪 + 试管）的新视频进来，只需要跑前端得到运动学参考，再把参考喂给这个 policy，就能在物理里生成可执行、自然的机器人动作：不抖，手指在不需要时不动，接触稳定。每条视频不再单独跑 MPC，也不手调。

数字的来源都标注了：**实测** 指我们自己跑出来的；**估计** 指推算的；**文献** 指论文自述、我们没有复现。

---

## 1. 问题怎么定义

**输出（动作）：** 关节目标 = 每条参考自己的 IK 解 + 抓握先验 + policy 残差。
- **IK 解：** 用 `common/arm_ik.py` 的 GPU DLS IK，对运动学参考的手腕目标求解。另外有每条参考自带的手指参考，以及按握姿文件补的 script_keep 和静止规则（`dataline/grasp_keep.py`、手指事件规则）。
- **抓握先验：** 握持段在手指参考上加挤压量，按 `mpc/stagebuild/squeeze.py` 的规则算，但要修正"两指段挤压不足"的已知问题，见第 2 节。
- **残差：** 手臂约 0.08 rad，手指约 0.25 rad，沿用 rrline 的标度，外加 EMA 0.5。
- **不以 MPC 示范为底：** 部署时完全不需要 MPC。和真机线（R1–R3，残差加在 T1_k 物理示范的 ctrl 上）的根本区别就在这里。

**观测（数据线只在仿真里用，可以用特权状态）：**
- 机器人关节位置和速度、上一步动作；
- 两个物体的位姿和速度；
- 未来参考窗口：沿用 rrline 的 `OFFSETS = (0, 2, 5, 12)` 步（0、40、100、240 ms），内容是手腕目标、物体目标、手指目标，都相对当前状态表达；
- 事件标志：将要抓或放、握持中、按压中，以及距离下一个事件的时间；
- 架子位姿（参考已经对它重新锚定）。

真机学生才需要的"只开局量一次物体位姿 + 手指电流"，这条线用不上。以后要上真机，再走 teacher→student。

**参考库：** 每个世界在开局时从参考库里抽一条参考和一组增强参数（见第 3 节），再随机抽一个起点（RSI）。env 目前只支持一条参考，要改成"按世界索引的填充参考库"，并加时间伸缩。见第 6 节。

## 2. 难点：没有逐视频物理示范，怎么学会握力

**我们自己的证据：**

| 证据 | 结论 |
|---|---|
| `common/RESULTS.md`，**实测**：运动学参考、零动作，VOC=1 时 13/13 走完；VOC=0 时只有 1/13，试管 1–5 s 就掉 | 运动学参考本身拿不住东西，握力全靠学，或者靠先验 |
| 同一个 env 的 PPO 冒烟（12 min，1140 万步）**实测**：和零动作没差别 | 没有扰动、没有课程，学不到东西 |
| 探索噪声 N(0, 0.3) 0.5 s 内就把握持抖掉，**实测**；只能用 0.1 | 探索必须很小，或者加平滑 |
| G1 W2_s1 RL（无扰动）**实测**：等于零残差，还弄坏了 5 项握持 | 没有失败就没东西可学 |
| R1/R2 **实测**：在物理示范上做残差 RL，加大范围扰动后，从头完成率从零残差的 2/64 提到 42/64 | 底子好、扰动大，RL 就有效 |
| T1 系列 **实测**：推算的挤压量（只有外展）4 次掉 3 次；手调的挤压量（拇指 ip +0.61 rad）6 次全部拿住 | 先验必须带"拇指屈曲"这类真正产生力的分量 |

**四个机制和推荐：**
- **(a) 虚拟物体控制器（VOC），逐步撤掉：** 已有实现（`common/vega_env.py` 的 `_voc`，PD 力和力矩把物体拉向参考，按世界设 scale）。按成功率自动降 scale，目标是 1 → 0。风险是撤不干净：文献（DexMachina、CHORD）都强调要先让接触项收敛再撤。
- **(b) 接触目标奖励 + 挤压先验：** Jiming 的 T1–T3 已在 rrline 实现，挤压规则在 squeeze.py。先验让零残差在 VOC=0 时就有一定握力，RL 只需修正。
- **(c) 用已有 MPC 示范做 BC 热启动：** 只用训练集视频的示范（T1_k；01 物理通过后也加上）。部署时仍然不需要 MPC。缺点是热启动偏向这几条参考，需要大扰动才能泛化。
- **(d) 握姿原语 + 残差：** 本质就是 (b) 的先验部分，握姿文件已经按物体和视频自动生成。

**推荐：(d)+(b) 做底，(a) 做课程，(c) 做后备。** 也就是：动作底 = IK + 握姿先验（挤压）；奖励里有 T1–T3；VOC 从 1 起步，按成功率撤到 0。如果 Stage 0 在 VOC < 0.3 时成功率塌掉，再引入 (c)。

挤压先验要先修：两指段必须有拇指 ip 屈曲分量（参照 E1：ip +0.61 rad，中指 pip +0.12 rad）。具体做法是在 squeeze.py 里把屈曲方向的推力也计入（stagebuild 已记下这条教训），或者直接把 E1 的分量作为"同类握姿"的模板。

## 3. 训练参考从哪来：不靠很多手工视频

**用户的顾虑：** 如果要很多条视频、每条都手工走一遍才能训出它，那还不如直接生成数据。

**回答：** 训练用的是**运动学参考**，不是物理示范。运动学参考由自动前端产生：重建 → 深度配准 → 纠错规则 → 每视频握姿 → 最小偏离重定向。这一路已经通用化，只花 CPU 几分钟加一次 GPU 搜索，不需要 MPC，也不需要手调。MPC 物理示范最多只给 (c) 热启动用一两条。逐视频最慢、最依赖人工的物理那一步，正是这个 policy 要替代的。

**参考来源：**
- 真实视频：run01（T1 布局下已有完整链）、01（数据线链已到 build），02 **永远留出**作最终测试。
- 自动增强，每个世界随机：
  - 架子和枪架平移 ±5 cm、转 ±10°，以及 88 对换孔。rrline 已实现，**实测** R2 能泛化到留出孔对和超范围挪位。
  - 时间伸缩 ×0.75–1.3（整体，加局部分段），新加。
  - 握持转角 psi 在可行集合内变化（右手 {−25…+30} 的可行点，左手按 reach 搜索）。
  - 接近和撤离路径变化：合成段的入射方向在无碰撞候选里随机取。
  - 物体初始偏移 ±2 mm、±3°；物理 DR 同 R3（阻尼耦合）。
- 这样总共是 2 条真实参考 × 上百种增强组合。

**需要多少多样性，怎么判断泛化有没有成（估计）：** 分三层留出：
1. 留出的增强参数，比如没训练过的时间伸缩和孔对。
2. 交叉留出：只用 run01 训，测 01；再反过来。
3. 02 从头到尾不碰，只做最终测试。

第 1、2 层过了才测 02。

**最少几条真实视频：** 2 条训练 + 1 条留出测试。判定规则：
- 如果第 1 层过了、第 2 层过不了，说明 2 条视频的多样性不够。这时补 3–5 条新视频的**运动学参考**，仍然不需要它们的物理示范，成本是前端几分钟一条。
- 如果第 2 层也过了、02 还是不行，说明前端对新视频的产出质量才是瓶颈（比如 01 暴露出的重建误差），要修前端，不是修 RL。

## 4. 奖励和验收

**奖励**（沿用真机线 R3 的实现）：
- 跟踪：物体轴点、手腕、手指、整体；
- Jiming 的三项接触：接触集合、接触图、受力支撑；
- 自然度：`finger_still`、`finger_band`、`arm_band`（这三项只算偏离参考的部分）、动作变化率、肘不高过肩、关节余量；
- 任务：`tube_tilt`、类似 `pipette_seat` 的落座项、按压深度；
- 试管自转不罚。
- 合成段（无人手数据）的跟踪权重降低，只要求不碰撞、手指静止。

**验收：**
- 用和真机线相同的判据（`eval_rr` 加原因表、shake 块、手指静止、抖动带），加上数据线自己的判据（`gate/thresholds.yaml`、参考审计、偏离人手的上限），**在扰动下**测。
- **02 的成功定义：** 02 只跑自动前端链，不做任何针对 02 的调整，得到运动学参考后跑这个 policy，3 次 DR 抽样里至少 2 次满足：走完全程、枪和试管落座、按压合格、握持判据、自然度项全过，偏离人手在上限内。

## 5. 分阶段计划和 go / no-go

**Stage 0（本机 5080，约 1 天）：验证最大的风险，即不靠 MPC 底能不能学会握持。**
- 只用 run01，T1 布局，增强只开架子 ±2 cm、换孔、时间伸缩 ±20%。动作底 = IK + 修正后的挤压先验，不用 T1_k。VOC 课程从 1 撤到 0。
- 训练量 1.5–3 亿步。本机共享时约 8–15k 步/s，是**估计**，需要 4–8 h。
- **go 条件**（VOC=0、DR 关、从头 64 次）：
  - 走完 ≥ 50%，试管和枪都落座 ≥ 40%，按压合格 ≥ 70%；
  - 握持接触集合 T1 漏接触率 ≤ 0.1；
  - 空闲手指 ≤ 2°。
  - 对照：零残差 + 先验、VOC=0 的同样 64 次，作为 RL 的提升基线。
- **no-go：** VOC < 0.3 时成功率塌到零残差水平。这时改用 (c)，用 T1_k 做 BC 热启动重做 Stage 0。

**Stage 1（节点 2 卡 × 约 4 h）：两条真实参考 + 全增强，做交叉留出。**
- 训练量 5–10 亿步。节点每卡约 2 万步/s（rrline env **实测**），需要 7–14 GPU·h。
- go 条件：第 1 层留出 ≥ 训练分布的 80%；第 2 层交叉留出 ≥ 60%。

**Stage 2：** 测 02（只测一次，不调），再出视频，交给用户验收。

**主要风险，按大小排：**
1. 不靠 MPC 底学握力（Stage 0 专门验证）。
2. 2 条真实视频的泛化（第 3 节的三层留出）。
3. 自然度和成功率此消彼长（沿用真机线 R3 的做法，验收时两者都要过）。
4. 算力：全量约十几到几十 GPU·h，需要节点。
